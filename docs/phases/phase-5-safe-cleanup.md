# Phase 5 — Safe Cleanup Engine

> **Goal:** Build the cleanup engine — the phase where StackSweep graduates from a reporting tool to an action tool.
> Safety is the absolute constraint. The CLI **never** deletes anything automatically. Every candidate is identified, explained, sized, and explicitly confirmed by the user before any action is taken.

---

## Objectives

- Define `SafetyRule` in `packages/rules/` — the typed contract that gates all deletions
- Define `CleanupCandidate` linking a filesystem entry to its governing `SafetyRule`
- Implement `Cleaner` module in `packages/core/cleaner/` — identify → present → confirm → execute
- Implement interactive per-item confirmation prompt with `[y] Yes  [n] No  [a] Yes to all  [q] Quit`
- Implement `--dry-run` mode — shows what would be deleted, does nothing
- Write a cleanup log to disk after each run
- Handle errors mid-cleanup: log and continue, do not abort the entire session
- Implement `stacksweep clean`, `stacksweep clean --dry-run`, and `stacksweep clean --dev`

---

## Core Principle

Every deletion must pass through this exact sequence. No exceptions, no shortcuts:

```
1. Identify candidate (path + size + matching SafetyRule)
2. Display item to user (path, size, what it is, why it's safe to remove)
3. Prompt for explicit confirmation
4. Only if confirmed: attempt deletion
5. Record result (success or failure) to cleanup log
6. Continue to next item
```

This flow cannot be bypassed by any flag, configuration, or environment variable.

## Data Model

```typescript
// packages/types/src/cleanup.ts

/**
 * A typed rule that authorises the cleanup of a specific class of paths.
 * Defined statically in packages/rules/. Each rule covers one category of
 * cleanup (e.g. Xcode DerivedData, npm cache, Trash).
 */
export interface SafetyRule {
  id: string                    // e.g. 'xcode-derived-data', 'npm-cache', 'trash'
  name: string                  // Human-readable: "Xcode Derived Data"
  description: string           // What this data is
  whySafeToRemove: string       // Explanation shown to user before confirming
  category: CleanupCategory
  requiresConfirmation: true    // Always true in Phase 5 — reserved for future
  pathPatterns: string[]        // Glob patterns this rule governs
}

export type CleanupCategory =
  | 'xcode'
  | 'docker'
  | 'package-manager'
  | 'python'
  | 'jvm'
  | 'system'
  | 'user-data'
  | 'cache'
  | 'logs'
  | 'temp'

/**
 * A specific file or directory on disk matched to a SafetyRule.
 * The unit of work in the cleanup pipeline.
 */
export interface CleanupCandidate {
  path: string
  sizeBytes: number
  rule: SafetyRule
  source: 'analyzer' | 'dev-detector' | 'duplicate-finder'
}

/**
 * The decision made by the user for a single candidate.
 */
export type ConfirmationDecision = 'yes' | 'no' | 'yes-to-all' | 'quit'

/**
 * The result of attempting to delete a single candidate.
 */
export interface CleanupItemResult {
  candidate: CleanupCandidate
  decision: ConfirmationDecision
  success?: boolean
  errorMessage?: string
  freedBytes: number            // 0 if skipped or failed
}

/**
 * The final summary after a cleanup session completes.
 */
export interface CleanupSessionResult {
  startedAt: Date
  completedAt: Date
  dryRun: boolean
  totalCandidates: number
  confirmedCount: number
  skippedCount: number
  failedCount: number
  totalFreedBytes: number
  results: CleanupItemResult[]
}
```

## Cleaner Module: `packages/core/cleaner`

```
packages/core/src/
└── cleaner/
    ├── index.ts            # Public API: runCleanup()
    ├── identify.ts         # Match CleanupCandidates to SafetyRules
    ├── prompt.ts           # Interactive confirmation prompt loop
    ├── execute.ts          # Performs the actual deletion
    └── log.ts              # Writes the cleanup log to disk
```

### `identify.ts` — Candidate matching

```typescript
/**
 * Given a list of CleanupCandidates (from analyzer or dev-detector),
 * cross-reference with the provided SafetyRules.
 * Only candidates matched by a rule are returned — unmatched candidates are silently dropped.
 */
export function matchCandidates(
  candidates: AnalysisCandidate[],
  rules: SafetyRule[],
): CleanupCandidate[]
```

Matching is path-based: use `micromatch` to test each candidate's path against each rule's `pathPatterns`. The first matching rule wins. Candidates with no matching rule are excluded from the cleanup session.

### `prompt.ts` — Interactive confirmation loop

```typescript
export async function runConfirmationLoop(
  candidates: CleanupCandidate[],
  options: { dryRun: boolean },
): Promise<CleanupItemResult[]>
```

For each candidate (in order):
1. Print the item details (see confirmation prompt design below)
2. Prompt for decision using `@inquirer/prompts` `select` prompt
3. If `yes`: call `execute.deleteItem(candidate)` (or skip if dry-run)
4. If `no`: record as skipped
5. If `yes-to-all`: set a flag — all subsequent items auto-confirm without prompting
6. If `quit`: stop processing remaining candidates, return results collected so far

### `execute.ts` — Deletion

```typescript
export async function deleteItem(candidate: CleanupCandidate): Promise<CleanupItemResult>
```

**Steps:**
1. Verify the path still exists — if not, log as "already deleted", record `freedBytes: 0`, continue
2. Check the path still matches the governing rule's `pathPatterns` — double-check before deleting
3. Attempt `fs.rm(path, { recursive: true, force: true })`
4. On success: record `freedBytes: candidate.sizeBytes`
5. On failure (EACCES, EBUSY, etc.): record `errorMessage`, set `success: false`, **do not throw** — continue to next item

## Confirmation Prompt Design

Each item is presented as a clear, informative block before prompting:

```
  ─────────────────────────────────────────
  Item 3 of 12

  Path:    ~/Library/Developer/Xcode/DerivedData
  Size:    38.1 GB
  Rule:    Xcode Derived Data
  
  What is it?
    Build artifacts generated by Xcode for each project.
  
  Why is it safe to remove?
    Derived Data is fully regenerated the next time you build a project in Xcode.
    Removing it does not affect your source code, settings, or app archives.

  ? What would you like to do?
  ❯ [y] Delete this item
    [n] Skip this item
    [a] Delete this and all remaining items
    [q] Quit without deleting anything else
  ─────────────────────────────────────────
```

**Implementation notes:**
- Use `@inquirer/prompts` `select` for the prompt — keyboard-navigable, no raw readline
- Highlight the size in bold yellow to make it immediately scannable
- After deletion, print a confirmation line: `✔ Deleted — 38.1 GB freed`
- After skipping, print: `– Skipped`
- After failure, print: `✖ Failed: <error message>`

## Dry-Run Mode

`--dry-run` runs the full identify → present pipeline but skips the confirmation prompt and all deletions.

Each item is displayed as it would be in a real session, with a `[DRY RUN]` prefix:

```
  [DRY RUN] Would delete: ~/Library/Developer/Xcode/DerivedData   38.1 GB
  [DRY RUN] Would delete: ~/.npm                                    2.1 GB
  [DRY RUN] Would delete: ~/.Trash                                  1.4 GB
  ─────────────────────────────────────────
  [DRY RUN] 3 items, 41.6 GB would be freed. Nothing was deleted.
```

Dry-run mode is the recommended first step before any real cleanup. Document this prominently.

## What Cannot Be Cleaned

The cleanup engine enforces a strict allowlist model. A file or directory can **only** be deleted if:
1. It appears in the candidates list (from analyzer, dev-detector, or duplicate-finder)
2. Its path is matched by an existing `SafetyRule`'s `pathPatterns`

Any path that fails either check is silently dropped before the confirmation loop. This means:
- System files (`/System`, `/Library`, `/usr`) — no SafetyRule covers them, so they can never be targeted
- Source code directories — not covered by any rule
- Paths outside of `~/` — no rule matches them unless explicitly added

## CLI Commands

```bash
# Review and interactively clean all identified candidates
stacksweep clean [options]

Options:
  --dry-run     Show what would be deleted without deleting anything
  --dev         Only show and clean developer storage (from Phase 4)
  --json        Output CleanupSessionResult as JSON after session ends
  -h, --help    Display help for command
```

### Command behaviour matrix

| Command | Candidates source | Prompts user | Deletes |
|---|---|---|---|
| `stacksweep clean` | Analyzer candidates + dev storage | Yes | Yes, per confirmation |
| `stacksweep clean --dry-run` | Analyzer candidates + dev storage | No | No |
| `stacksweep clean --dev` | Dev storage only (Phase 4) | Yes | Yes, per confirmation |
| `stacksweep clean --dev --dry-run` | Dev storage only | No | No |

## Error Handling

| Error | Behaviour |
|---|---|
| File not found at deletion time | Log as "already deleted", `freedBytes: 0`, continue |
| Permission denied (EACCES) | Log failure with message, continue to next item |
| File locked / in use (EBUSY) | Log failure with message, continue to next item |
| Path no longer matches rule patterns | Abort deletion for that item, log as "safety check failed", continue |
| Log file cannot be written | Print warning to stderr — do not abort the cleanup session |
| No candidates found | Print info message: "No cleanup candidates found. Your system looks clean." Exit 0. |

## Unit Tests

- `identify.ts` — `matchCandidates()`: candidates whose paths match a rule pattern → returned; candidates with no matching rule → excluded
- `identify.ts` — path pattern matching: assert `micromatch` correctly matches `~/Library/Developer/Xcode/DerivedData/ProjectX` against `~/Library/Developer/Xcode/DerivedData/**`
- `prompt.ts` — mock `@inquirer/prompts`: assert `yes-to-all` sets flag correctly so subsequent items skip the prompt
- `prompt.ts` — assert `quit` stops processing and returns partial results
- `execute.ts` — mock `fs.rm`: success case → `success: true`, `freedBytes` matches candidate size
- `execute.ts` — mock `fs.rm` throwing EACCES → `success: false`, `errorMessage` set, no re-throw
- `execute.ts` — path no longer exists → `success: true`, `freedBytes: 0` (not an error — file was already gone)
- `log.ts` — given a `CleanupSessionResult` fixture, assert log file contains correct lines in correct format

- Spawn `stacksweep clean --dry-run` with a mocked set of candidates
- Assert: no `fs.rm` calls are made
- Assert: stdout contains `[DRY RUN]` prefix for each item
- Assert: final summary states "Nothing was deleted"
